## 1. 总体

- 通道：AXI4-Lite 从接口，32 位数据，基地址由 Vivado 地址编辑器分配（`0x4000_0000` 起，默认）。
- PL 侧模块 `axi_lite_regs.sv` 实现，host 侧 `backend_fpga.py` 使用 `/dev/mem` mmap 访问。
- 既有时钟候选：板上差分200MHz `PL_CLK0`（H24/G25）→MMCM→100MHz控制+200MHz UART。CDC必须显式设计，不会因寄存器存在而自动同步。
- 第一版另提单100MHz方案以减少CDC，尚待评审；具体来源/复位/AXI跨域须按Z19参考BD核验，见FPGA技术设计。

## 2. 物理层与引脚分配（v0.2 新增）

### 2.1 舵机总线拓扑（待定项 3 定稿）

- **单总线**：1 条半双工 TTL 总线串联 8 × SCS0009（ID 1~8），1Mbps，与官方装配指南接线一致（官方 `PythonExample` 即单串口 `baudrate=1000000` 驱动 8 舵机）。
- 舵机ID↔手指映射（固定版本Demo）：ID1/2食指、3/4中指、5/6无名指、7/8拇指；每指两舵机的机械耦合/作用需队长确认，不预设独立屈曲/外展。
- 带宽预算见§6：1kHz下发+每周期回读2路不可行；500Hz/2路为首版待测候选，1kHz/1路需测量余量。
- 升级路径：若实测回读带宽不足，FMC1 LA03~LA09 空闲可扩第二总线，RTL 按参数化通道数设计。

### 2.2 电平转换（硬约束，必须）

- FMC1数据IO为BANK67/68，按手册J5选1.8V/1.2V，本项目候选为1.8V；不把此约束推广成“全部PL IO均为HP”。
- 舵机侧逻辑电平按实际型号/接线核实；若为5V，严禁直连1.8V的FMC数据IO，必须电平转换。
- **历史选型候选，待实测签收**：TXS0108E模块（TI现行数据表VCCA 1.4~3.6V、VCCB 1.65~5.5V，具体速率/负载条件查数据表）：
  - A 侧接 FMC1 `VADJ`（1.8V）与 `LA02_P`；
  - B 侧接舵机总线 DATA 与舵机 5V；
  - 自动方向不替代PL输出三态；最后停止位后释放DATA，响应期高阻。多节点线缆的换向/反射/负载需实测，不能推断“无冲突”；
  - 仅用 1 通道，其余 7 通道留作升级。
- 转接板采购组合（无现成单板方案）：
  1. FMC1 HPC → 2.54mm 排针裸转接板（引出 LA + VADJ + GND）；
  2. TXS0108E模块（历史选型，价格/可采购性本次未核实）。
- 舵机供电：历史BOM为外置5V/2A，但实际额定值、8路峰值和压降尚待确认；严禁从VADJ/FMC取电。

### 2.3 PL 引脚分配（引脚号实测自《Z19 用户手册》）

| 信号 | 物理位置 | ZU19EG 引脚 | 方向 | 电平 | 用途 |
|---|---|---|---|---|---|
| `SERVO_DATA` | FMC1 LA02_P | L17 | inout | LVCMOS18 | 舵机总线数据（经 TXS0108E） |
| `SERVO_DATA_SPARE` | FMC1 LA02_N | K17 | inout | LVCMOS18 | 预留第二总线 |
| `PL_CLK0_P` / `PL_CLK0_N` | 板载晶振 | H24 / G25 | in | 差分 | 200MHz 系统时钟 → MMCM |
| `HEARTBEAT` | 板载 PL_LED1 | B3 | out | — | 1Hz 心跳 |
| `ESTOP_N` | 板载 PL_KEY | D4 | in | — | 急停按键（低有效，直连 grasp_fsm 保护逻辑） |

- xdc候选：FMC实测J5为1.8V时用LVCMOS18；LED/KEY电平单独查原理图，不推广“全部PL为HP”。
- `ESTOP_N`同步后尽快锁存保护，释放/重新使能消抖；上拉与低有效按实际板级电路核验，按键不是已验证的独立电源切断器。
- 板载 PL_UART（C3/C6，经 CP2102 接 PC）保留为调试通道（tx_eeprom 类辅助），不接舵机。

## 3. 寄存器映射（偏移 = 基地址 + offset，v0.1 不变）

### 控制区（host → PL）

| 偏移 | 名称 | 字段 | 说明 |
|---|---|---|---|
| 0x00 | CTRL | [0] enable, [1] mode(0:直接角度/1:状态机), [2] estop | 使能与急停 |
| 0x04 | CMD | [7:0] cmd, [15:8] arg | 0x01=启动抓取 0x02=释放 0x03=预张 0x04=力矩使能(arg 1/0) 0x10=回中 |
| 0x10+i*4 (i=0..7) | TARGET_i | [11:0] 角度(0.1°单位), [15:12] 舵机ID | 各舵机目标角 |
| 0x30 | TORQUE_LIM | 每 4 位一个通道，0~15 级 | 力矩上限（对应 SCS Load 限幅） |
| 0x34 | TIMING | [7:0] 闭合速度, [15:8] 轮询周期(×0.1ms) | 1kHz 默认 |

### 状态区（PL → host）

| 偏移 | 名称 | 字段 | 说明 |
|---|---|---|---|
| 0x80 | STATUS | [0] fsm_busy, [1] grasped, [2] timeout, [3] fault | 主状态字 |
| 0x84 | FSM_STATE | [7:0] 状态编码 | IDLE/PREGRASP/CLOSING/HOLD/RELEASING/PROTECT |
| 0x90+i*4 (i=0..7) | MEAS_i | [11:0] 角度, [15:12] 标志 | 最近一次回读位置 |
| 0xB0 | LOAD_i | 0xB0+i*2，16 位半字 ×8 | 回读力矩（SCS Load 原始值） |
| 0xD0 | TEMP | [7:0] 最高温度通道, [15:8] 温度值 | 过温监视 |
| 0xE0 | ERR_BITMAP | 每位一通道 | 堵转/掉线/超温位图 |
| 0xF0 | TIMESTAMP | 32 位循环计数 | 供 host 测环周期抖动（对比实验用） |

## 4. 中断（既有规划，未实现）

- PL → PS 一根中断（AXI INTC）：触发条件 = FSM 状态跳变 或 ERR_BITMAP 非零。
- host 侧收到中断后读 STATUS/ERR_BITMAP，驱动 UI 与日志。

当前Host后端实际为mmap读写与应用轮询，没有IRQ应用处理；启用中断需驱动/UIO与设备树配套，不能把本节规划写成已有功能。

## 5. 软件环后端（backend_serial.py，对比基准）

- 通道：USB-TTL（Waveshare 总线驱动板，PS USB3.0 口，`/dev/ttyUSB0`），1Mbps 半双工。
- 当前serial后端逐舵机WRITE位置/速度并等回应，未采用§6同样帧序列，FSM也有差别；公平对比前需统一协议profile、报文/调度和保护策略。
- 轮询：Python 循环 + `time.perf_counter()` 打点，记录环周期直方图 → `data/metrics/`。

## 6. 单总线时隙调度（v0.2 新增）

当前代码使用0x2A起连写6B（位置2B+Goal_Time2B+速度2B），不是原来的4B。
以下只复算帧结构与线路下界：1Mbps、8N1、10bit/字节。当前模型的SCS0009端序/地址/换算与上游资料有冲突，需实机核验，不能称硬件协议权威。

| 时隙 | 事务 | 帧长 | 耗时 |
|---|---|---|---|
| t0 | SYNC_WRITE(0x83)，8舵机，每路6B | 64B | 640µs纯线路时间 |
| t1 | READ舵机#i，8B反馈（实际起点待核验） | 8B请求+14B响应 | 220µs纯线路时间 |
| t2 | READ舵机#j（同上） | 同上 | 220µs纯线路时间 |
| 合计 | 不含返回等待、换向和间隔 | 108B | **1080µs，已超过1ms** |

推导：SYNC_WRITE params=1+1+8×(1+6)=58B，LEN=60，帧总长64B。
READ响应LEN=err1+data8+checksum1=10，帧长4+10=14B；请求为 `FF FF ID 04 02 addr len CS`，共8B。

- 第一版建议500Hz下发＋每周期2路回读，8路完整轮询约8ms（每路125Hz），待真实时延和保护要求验证后冻结。
- 1kHz＋每周期1路回读仅有140µs非线路预算，全8路轮询仍约8ms；不代表已实测可行。
- 关键4路轮询可缩短其反馈间隔，但其余通道的最大反馈年龄/温度/掉线监视不得失去保证。
- 超时需分首字节、字节间、事务整体三个定义；100µs不能作为完整响应截止（响应本身140µs）。错误位图布局也需与Host统一。
- `servo_bus_ctrl.sv`尚未实现；目标为固定时隙、异常有界，周期独立于PS调度；物理反馈频率仍受总线限制。
