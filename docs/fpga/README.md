# FPGA 开发计划与实施路线

版本：规划草案 v1.0，2026-10-05。代码基线：`main@7a5477f`。
适用硬件：ALINX Z19，`XCZU19EG-2FFVC1760I`。
第一版截止：**2026-10-15 前，即最迟 10-14 完成验收与交付**。

## 1. 已确认的目标与职责

本项目仍沿用“人手持手、PS 负责感知与策略、PL 负责确定性总线控制与保护”的思想。
PL 接收抓取计划，驱动单条半双工总线上的 8 个舵机，回读反馈，在接触、异常或急停时按约定停止或保护。
第一版必须完成 **Z19 的 PL 实际驱动灵巧手抓取并释放**。仅有仿真、LED、串口软件控制或无实物的板上自测，均不能代替该验收。

用户已确认：本人负责 PL RTL、仿真、Vivado 工程、PS↔PL 接口和板端加载联调；队长负责机械、舵机标定、视觉语音与抓取策略。
Z19 配套齐全，已安装 Vivado/Vitis 2020.1；实验室有示波器，无独立逻辑分析仪。
舵机、FMC 转接板、电平转换、电源的可用状态和最早联调日期尚不清楚。
本计划建议在 10-06 与队长核实这些依赖；这是待办，不代表已经联系或得到答复。

第一版推荐候选：**500Hz 下发，每个 2ms 周期回读 2 个舵机**，8 个舵机完整轮询约 8ms。
先用宽松周期完成单舵机联调，再以真实测量确认 500Hz。1kHz 优化安排在基础闭环验收之后。
用户没有指定频率方案；500Hz 是本文件的工程建议，仍需接口评审和测量后冻结。

## 3. 现状审计：已有东西能复用到什么程度

| 范围 | 仓库证据 | 截至本轮的真实状态 | 对 FPGA 的用途/限制 |
|---|---|---|---|
| 项目思想 | `docs/project_framework.md`、`docs/design/architecture.md` | 已有设计文档；其中部分说法过时 | 保留 PS/PL 分工，按本次审计处理冲突 |
| 协议参考 | `host/app/control/scs_protocol.py` | 有组包/解析代码；27/27 现有冒烟通过 | 可复用帧结构测试方法；字节序、地址、换算需重验 |
| 虚拟舵机 | `host/app/control/scs_sim.py` | 有模型和故障注入 | 仅功能验证；没有真实 UART 时间、电气或动力学保证 |
| Host 抽象与主流程 | `servo_base.py`、`main.py`、`backend_sim.py` | 骨架可空转；10/10 后端冒烟通过 | 同一输入契约可作为联调入口；行为仍有审计缺口 |
| FPGA Host 后端 | `backend_fpga.py` | 有 `/dev/mem` 访问骨架；未验证 PL 寄存器 | 不是已完成 FPGA 链路；编码、反馈、快照需同步修订 |
| 串口 Host 后端 | `backend_serial.py` | 有软件后端；本轮未接实机 | 帧调度/FSM 与 sim 不完全相同，不能直接做公平性能结论 |
| 抓取表 | `grasp_table.json` | default、banana、apple、bottle 均 `source=default` | 占位参数不可直接用于整手安全验收 |
| PL 工程 | Git 跟踪文件与工作区核对 | 无 `fpga/`，无 RTL/TB/XDC/Tcl/.bit/.xsa | 需要从可复现的最小工程开始建设 |
| 上游灵巧手 | Gitlink `AmazingHand` 固定 `3e824107…` | 当前目录无已展开源码；无 `.gitmodules` | 本轮只远程只读核对固定版本 Demo；不宣称本地可复现 |
| 工具 | `F:/Xilinx/Vivado/2020.1`、`F:/Xilinx/Vitis/2020.1` | Vivado batch 启动与目标器件查询成功 | 未检验综合许可、完整构建、JTAG 或 Linux 镜像 |
| 实物状态 | 旧日志 + 用户最新说明 | 旧日志曾称手已装配；本人当前无法确认可用状态 | 不能把历史记录当成本轮实物验收 |

本轮验证仅说明现有 Python 测试和工具查询结果，不说明真实舵机、RTL 或抓取已经通过。
具体审计发现与证据见 [验证文档 §2](verification_acceptance.md#2-多方面审查记录)。

## 4. 工作包与交付职责

R 为执行负责人，A 为该工作包技术签收人；代码合入仍需另一名队员 Review/Approve 和人工合并。

| 工作包 | 本人（FPGA） | 队长（灵巧手/PS） | 必须交换的交付物 |
|---|---|---|---|
| 硬件接入 | R：FMC、转换器、UART 电气测试 | A/R：舵机、电源、机械安全和实物提供 | 实物清单、接线照片、端子定义、示波器截图 |
| 协议与标定 | R：帧时序、RTL字段、采样接口；共同核验 | A/R：舵机型号固件、中位、方向、安全行程 | 固定版本寄存器表、有效字节序、原始报文、标定表 |
| PS↔PL 契约 | A/R：AXI与寄存器硬件语义 | R：Host 编解码与调用顺序 | 双方评审的版本化接口、相同测试向量 |
| RTL与仿真 | A/R：全部 PL 源码、TB、故障路径 | C：提供真实机械约束、复核抓取结果 | 回归日志、波形、覆盖清单 |
| 工程与板端 | A/R：BD/XDC/Tcl、bit/XSA、加载联调 | R：Linux 应用、运行依赖与策略接入 | 地址导出、时钟复位、构建/加载记录 |
| 第一版抓取 | R：稳定总线/反馈/保护、测量数据 | A/R：确认安全对象与抓取姿态，现场操作者 | 同一对象真实抓取/保持/释放记录 |
| 视觉语音 | C：接口适配、系统联调 | A/R：识别、引导、抓取表 | 已验证的 GraspPlan；不阻塞手动触发的 PL 验收 |
| 可选 DPU | 第一版之后另立任务 | 共同评估模型与镜像 | 必须先有稳定基础闭环；本次不承诺实现 |

本人不承担机械重新设计、视觉模型训练、相机/语音算法或抓取参数凭空定值。
第一版允许用手动 CLI 触发队长给出的已标定抓取计划，验收动作必须经过 PS→AXI→PL→真实舵机。
这只缩小第一版感知入口范围，不降低真实抓取要求。

## 5. FPGA 工作拆解

| 编号 | 工作内容与计划路径 | 优先级 | 输入依赖 | 完成判据 |
|---|---|---|---|---|
| W0 | 版本/许可/器件、Z19 参考工程、时钟 LED 自测 | P0 | Z19/JTAG/官方例程 | 最小 bit 可构建、上板可观测 |
| W1 | 实机协议核验、Python 基准纠正、标定交接 | P0 | 单舵机、受控供电、队长 | 真实 PING/READ/小幅位置写入与独立报文一致 |
| W2 | `fpga/rtl/half_duplex_uart.sv` | P0 | 经核验电气/时钟方案 | 8N1、1Mbps、换向、异常和复位 TB 通过 |
| W3 | `fpga/rtl/scs_protocol.sv` | P0 | W1 固定协议 | 组包/校验/解析逐字节对照独立向量 |
| W4 | `fpga/rtl/axi_lite_regs.sv` | P0 | 双方冻结接口 | AXI背压、WSTRB、影子提交、错误写入验证 |
| W5 | `fpga/rtl/servo_bus_ctrl.sv` | P0 | W2/W3 | 时隙有界、轮询公平、超时不拖垮总线 |
| W6 | `fpga/rtl/grasp_fsm.sv` + 保护路径 | P0 | 反馈有效性、标定参数 | 预张/闭合/保持/释放、全状态保护验证 |
| W7 | `fpga/rtl/top.sv`、`fpga/constr/z19.xdc`、`fpga/scripts/build_project.tcl` | P0 | 官方 PS preset、W0/W4 | 全流程可复现，BD/DRC/时序通过 |
| W8 | `host` 接口适配、板端加载、真实单舵机→8路 | P0 | W1/W7，队长软件交付 | 可读版本、可提交目标、有反馈及故障记录 |
| W9 | `fpga/sim/`、ILA、指标与报告归档 | P0 | 各模块同时建设 | 功能、保护、性能、真实抓取证据齐全 |
| W10 | 1kHz 调度优化、多总线/DPU | P1/P2 | 第一版全部 P0 完成 | 独立实验；不得挤占 10-14 验收 |

P0 是第一版必须项；P1 为测量后优化，P2 为后续扩展。各模块 TB 与实现同时写，不能全部拖到最后。
W1/W4 可与 W2 的基础 UART 并行推进；未经 W1 核验，不冻结 SCS 字段和真实机械动作参数。

## 7. 第一版提交物

1. RTL、TB、约束、IP/BD可复现配置、构建/仿真脚本，及工具/IP版本说明。
2. 固定版本 PS↔PL 接口、Host适配、舵机协议与标定数据；参数来源清楚。
3. 对应 Git commit 的 `.bit`、`.xsa`、ILA `.ltx`（若使用），实现/资源/时序/DRC/CDC报告。
4. Z19 板端加载与启动步骤、真实8路抓取/保持/释放演示、保护和故障记录。
5. 原始测量数据及条件、P99等统计定义；未测或未通过项如实列出。
6. 复现说明与开发日志；本次规划文档不能代替上述后续工程交付。

现有 `.gitignore` 不作本轮修改。它保留多数硬件产物，但 `fpga/build/out/*` 被忽略；未来发布时先审查保留策略与体积限制，避免误丢 bit/XSA/报告或跟踪大缓存。
