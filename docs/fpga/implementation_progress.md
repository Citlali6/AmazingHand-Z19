## 当前环境

- PC 为 Windows；本次没有安装虚拟机、WSL 发行版或大型 FPGA 工具。
- 所有新构建包与日志位于 F 盘 `tmp/`，属于可重建产物，不纳入 Git。
- 学长 BOOT/内核基线为 PetaLinux 2020.2 / Linux 5.4，根文件系统 glibc 2.30 / Python 3.7。
  板端 Python 3.11 与 NCNN wheel 的运行兼容性须在系统启动后验证；不向 Windows 安装 ARM64 包。
- 已有 Vivado/Vitis 2020.1；相机集成工程使用 2020.2，安装匹配工具前核算 F 盘容量与许可。
- SD 序列号是 USB 读卡器暴露的身份；移入板卡后以 SD 类型、MBR PARTUUID 和完整分区几何交叉核对，拒绝 eMMC。
- 应用、模型、标定与持久日志目录已经写入根分区安装脚本；日志实际位于 `/var/lib/amazinghand/log`，后续网络更新与替换配套启动文件通常保留根分区。
- 19:27 板端清单：正式 root 为 `/dev/mmcblk1p2`（PARTUUID `47fcfe04-02`），约 26 GiB 可用；A53 四核、Linux 可用总内存约 7442 MiB；Python 3.7.6、OpenCV 3.4.3、NumPy 1.17.0、GCC/G++ 9.2.0、Make 4.2.1、glibc 2.30。没有 pip、NCNN 或 PyYAML，未安装 Python 3.11。
- 基线启动没有 `/dev/mipi_cam` 或 `/dev/video*`。本次加载配套相机 bit 和原生编译的独立驱动后，`/dev/ah_camera0` 实际采集成功；设备和映射只适用于此 profile，重启需要重新加载。
- PS 网口为 `eth1` / `ff0e0000.ethernet`。当前网线直连电脑：PC 沿用已有 `192.28.14.152/24`，板卡改为 `192.28.14.153/24`，配置原件有备份；链路为 100 Mbps/full。SSH 登录和 8 MiB 上传/下载 SHA256 校验通过；电脑仍通过 Wi-Fi 上网，未配置板卡外网共享。

## RTL 基线检查证据

在独立 `tmp/rtl-baseline-20261010` 调用已安装的 `xvlog.bat --sv`，先编译含 package 的
`scs_protocol.sv`。编译器在第 58 行报告 `VRFC 10-1103`：开启 `default_nettype none` 时
枚举类型输入 `frame_type` 需要明确声明端口类型。尚未进行后续 elaboration 或仿真，不能计作通过。
另有源码审查发现 CTRL estop 位与契约冲突、AXI rready 声明缺失、地址默认值不一致等，
需在阶段 E 统一接口迁移和覆盖测试，不能以修好一个编译错误就签收实物控制。
