# 项目框架（现行）— Demo-first 视觉抓取工作站

> **2026-10-20 决策更新**：不再要求 FPGA/PL 先完成才允许真实机械抓取。优先用成品 RoArm-M2-S 官方 ESP32 固件和 Python SDK、实验室 USB 摄像头在 PC 上快速交付完整效果；Z19/PL 并行作为可验证的技术展示。旧可穿戴 AmazingHand 八舵机计划已退役，历史可从 Git 追溯。

## 作品简介

项目拟名《视觉引导智能抓取与 FPGA 辅助控制演示系统》（正式报名名称由队长对照竞赛要求决定）。面向实验室教学、桌面轻量分拣：PC 相机视频实时显示目标位置，用户确认物体后，原厂 RoArm-M2-S ESP32 执行安全的坐标/关节动作，真实夹取、搬运和投放，并在界面反馈运行过程。条件成熟再展示 Z19 FPGA 的硬件功能，不能把 Z19 的接入问题变为作品主线的阻断。

## 当前优先级与验收

| 等级 | 目标 | 标准 |
|---|---|---|
| R0 | 厂商 SDK 实体控制 | PC 查询实际反馈，小范围低速动作、夹爪可见开合，记录真实设备型号/固件 |
| R1 | 实体抓放 | 轻质方块从安全固定坐标到投放区，记录完整流程和失败 |
| R2 **必交** | 真实视觉抓放 + UI | 真实 USB 帧、标定变位、至少三个物体位置、抓取/释放/记录，可反复演示 |
| R3 并行争取 | 合理利用 Z19 PL | 复用已验证硬件链路，至少一项有实板证据的 PL 功能；**不串入 R2 关键路径** |
| R4 可选 | Vosk、NCNN、ROS2/更复杂对象 | R2 稳定且有足够时间才做 |

厂商 ESP32 负责底层舵机/IK，PC 承担视觉与控制；Z19 PS 及 PL 各有独立真实证据等级。PC-only 演示不能叫 FPGA 完整实物闭环，PL 的计划不能冒充已上板。按当届 FPGA 赛道正式规则核对最终 FPGA 交付要求；不假装只摆上板卡就符合比赛。

## 现成技术与依赖

机械臂标准整机已下单，未到货验证；实验室已有曾用于树莓派的 USB 摄像头，PC 测试优先，Z19 UVC 未确认不影响 PC。官方 [ESP32 固件](https://github.com/waveshareteam/roarm_m2) 与 [Python SDK](https://github.com/waveshareteam/waveshare_roarm_sdk) 核心源码公开，但本仓库当前**只有 SHA/API/许可证审计，没有全量源码快照**，由 [#14](https://github.com/Citlali6/AmazingHand-Z19/issues/14) 固定版本与 PC 环境。旧 IMX214/MJC1 R2 可借鉴，原未签收组合 bit 不能部署。

## 职责与操作规范

Citlali6 担任负责人及实体硬件唯一现场许可人，队员 A 负责 PC 视觉/标定/UI，队员 B 负责 RoArm SDK/真实运动/反馈，Codex 完成离线开发测试并提交 PR。#9 独立 FPGA 支线可并行做审计/简单硬件展示，不阻塞 #10 的 PC 视觉真抓放。

任何实际机械运动必须先固定底座、清空工作区、确认可安全独立断开 12V，人工批准后由现场人员进行。不可凭发送串口指令就宣称抓取成功，软件 STOP 不等于物理制停。禁止擅自升级系统、刷 ESP32 或覆盖已验证 FPGA 镜像。
