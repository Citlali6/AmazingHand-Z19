# Demo-first 决策：10 天内实物效果优先（2026-10-20）

> **本文件是用户确认后的现行技术路线决策**，替代此前“完成 FPGA 授权才能开始实物抓放”的前置条件。目标是做出安全、可重复、能现场展示的真正视觉抓取作品。修改此优先级须由 Citlali6 再次明确决定。本页是规划，不表示实际机械臂已验收。

## 1. 排序（发生资源冲突时严格按本排序取舍）

1. **P0-A：成品 RoArm-M2-S 能在电脑上通过官方 SDK 受控运动、夹取、搬运和放置实物**。机械臂出厂 ESP32 驱动/逆运动学优先复用，禁止因追求 FPGA 重写舵机内环；真实反馈、人工监督和合理物理断能仍是安全前提。
2. **P0-B：实验室 USB 摄像头 + PC OpenCV 的视觉定位→标定→变位抓放**。先彩色轻质方块和固定俯视工位，完成 3 位置的真实视觉引导演示；PC 视觉独立于 Z19 驱动。
3. **P0-C：演示稳定性与观感**。实时视频、框/坐标、当前目标、阶段和串口反馈、失败提示、手动控制、日志/视频复现，少功能但要稳定。
4. **P1：Z19/FPGA 合理参与系统**。争取展示既有或新增的实测 PL 状态采集/定时/任务辅助功能，但不得作为上述 P0-A/B/C 的运行条件。PS USB 与 PL 通信可并行探索；能用复用旧 MJC1 R2 就先审计复用，不做新的 MIPI+HIL 大合成任务。
5. **P2：Vosk 语音、多类别 NCNN、ROS2/MoveIt、DPU、复杂数字孪生、动态避障**。只有真正 P0 成功后才加入；继续保留旧研究成果。

**失败时的原则**：如果 Z19 FPGA 某项配置、PL 时序、相机驱动或 PS UART 适配被阻断，PC→USB→RoArm 的受控实体演示仍能继续开发和交付；不得放慢、回退或破坏已验证的 PC 流程去强行接 FPGA。

## 2. 与 ESP32 的真实职责

- 厂商 ESP32 固件完成舵机驱动、逆运动学、夹爪/末端控制；原厂固件和 SDK 的 API 真实存在，但到货固件版本/夹爪方向/运动特性仍待实测。
- PC 承担最先落地的相机采集、HSV/OpenCV、标定、抓取策略、任务控制、可视化；**早期可以直接通过 SDK 的 USB 串口控制机械臂，不经过 Z19**。
- Z19 有两个不同层：ARM Cortex-A53 PS 和 FPGA PL。后续可将视觉/控制从 PC 分阶段搬到 PS，或给 PL 加入真实可测的任务计时/状态监督；必须说明 **PS-only 不等于用到了 FPGA 逻辑**。为了竞赛展示 PL 参与，如有时间要记录对应 bit、寄存器/信号和实测效果，不以开着开发板/跑旧仿真冒充。
- 有或没有 PL 授权的**两种运行模式不得混淆**。PC 直接控制是 P0 主链；将来 PL 授权是独立可选模式。任何“PL 授权、硬件急停、FPGA 直接驱动电机、全板端视觉”的说法必须有对应设备的实测证据。软件 STOP 请求不能保证 ESP32 当前运动立即停止。

## 3. 逐步交付的可运行形态

| 等级 | 视频/日志看见什么 | 不要求什么 |
|---|---|---|
| R0 官方本机演示 | PC 经原厂 SDK 真实查询反馈；空载低速关节和夹爪动作 | 不要求 FPGA/视觉 |
| R1 实体抓放 | 固定已标定坐标、PC 下发受限动作，夹物、搬运、投放，显示反馈 | 不要求 FPGA/视觉识别 |
| R2 视觉闭环工作站（核心） | USB 相机真画面，改变方块位置后重新检测、标定坐标并抓放，完整 UI、日志与现场可重复演示 | 不要求 FPGA 作为机械命令前置 |
| R3 加分项 Z19 | 独立展示真实 PS/PL 协作功能，或审计通过后以可切换模式加入机械流程，明确 FPGA 控制责任、实验结果和恢复方式 | 不要求用 FPGA 重写出厂伺服 |
| R4 可选扩展 | 有空再加入离线语音/NCNN/更多物体等 | 不得影响 R2 稳定性 |

这不是鼓励“摆着 FPGA 就当交付”。**R2 与 R3 分别验收**；如参赛规则对 FPGA 参与有正式要求，交付材料须如实展示 R3 的真实功能及对应证据，不得虚构。先保证 R2，期间安排一个人低风险并行准备 R3。

## 4. 真实工程安全，不随优先级降级

- 机械臂首次上电可能有自启动运动：固定底座、确认供电、清空机械运动范围、能够安全断开 12V；由 Citlali6 现场验收并当次允许后才能发送实体运动。
- 第一版只使用低速、小行程、轻质物体与已测工作域；先 PC 查询/小角度/单阶段，再自动多阶段。
- 串口单进程拥有；坐标标定与限位验证、相机断流、反馈缺失、急停/停止请求/超时与人为确认都应在**PC 安全状态机**中独立成立。不得把“未使用 PL”当成跳过限位/安全检查的理由。
- 厂商 SDK 的命令返回不等于抓取成功；真正抓住与投放由真实观察/视频/日志证明。失电可能造成机械臂下垂，软件 `torque_set(0)` 非普适安全急停。
- 禁止 Codex 代替人在现场上电、接线、刷固件、操作 FPGA 或无授权下发真实机械动作；需保留设备可控与安全。
