# 2026-10-20 起 D1–D10 交付排期与人员分工

> **项目优先级：完整实物交付 > 可重复验收 > 安全与可信证据 > 扩展功能**。日历 D1=2026-10-20，D10=2026-10-29（如硬件快递晚到，立即按下表止损，不默默延后截止）。可用时间/比赛正式日期另由负责人对照官方通知确认。本表为工作计划，不是已发生事实。

### 双人并行原则

- A 处理视觉/坐标映射，B 处理原厂接口、PL授权桥；各自独立 Issue、独立分支、不同模块目录。
- 同一块 Z19 与实物机械臂不能被两个 Codex/队友同时操控。由 Citlali6 管理上板时段：任何时段仅一个“实体设备操作者”，另一人离线仿真或代码审查。
- 共同接口只在一次 PR 中明确冻结（字段/版本/单位/时间源/反馈语义）；修改必须先通知对方并更新测试；不要在多个开发分支覆盖同一 \`host/app/main.py\` 或每日日志。
- 不能在别的成员工作区执行 reset/clean、切换未授权 bit、替他人 Approve 或 merge。

## 3. 必须执行的止损检查

- **D2 夜**：机械臂物流尚不确定 → 催实际 ETA；不能凭页面“预计”认定已经到货。PC 侧 SDK/mock 可继续，项目风险升高。
- **D3 夜**：若 Z19 UVC 未恢复，切路线 B“PC视觉→Z19”；不可为 USB 摄像头重新安装 PetaLinux/内核作为十天内前置工作。
- **D4 夜**：若 PL+PS→RoArm 授权链没有真实进展，暂停视觉 UI/语音扩展，控制人员 100% 集中在最小硬件回路。PC 直接控制机械臂不等于 FPGA 任务已交付。
- **D5 夜**：若原厂 IK 在预定场景失败，降低到固定可达的盒子/定姿轨迹，保留真正的 FPGA 授权；不要在剩余时间开发新的 3D IK/碰撞规划。
- **D7 夜**：若视觉真实定位不稳定，选择单一高对比物品、固定光源与桌面，减少类别；仍必须对物体偏移测试，而不是用死坐标替代视觉。
- **D8 夜**：如仍未真实抓放，取消语音、报告美化、ROS2/LLM；全力修实体链路。若只能做到 FPGA→实体机械臂移动，无物体抓取，需明确降级交付与未达标原因，不得伪称完整。
- **D9 起**：冻结版本/接口，不擅自升级固件、换模型或改系统；任何“优化”须具备可回退成果与新证据。

## 5. 目标指标，不等于实测保证

- 演示阶段以“每次抓放能完成且无未授权动作”为硬条件。建议目标：3 个已标定位置，各做不少于 5 次完整尝试并逐次记录（真实结果可能不足目标，必须如实上报）；不能挑成功录像计算 100%。
- 视觉误差以标尺/毫米对照测量；同步给出视角、标定矩阵、桌面坐标单位、图像尺寸，不先写“毫米级”精度。
- 动作/STOP 延迟将“发出 STOP”“PS 不再发新指令”“机械臂物理停止”拆成三套指标；未测者写 NOT VERIFIED。
- FPGA 必须提供新实现的真实功能演示、测试结果、时序/资源证据；旧 MJC1 R2 的时序不能冒充新版本的。
