## 三、止损阈值（最高优先级：保住 R2）

- **D2 无机械臂**：催物流，同时完成 PC USB 视频、mock SDK、标定 UI，不等机械臂才能开始研发。
- **D3 原厂 SDK 不兼容**：先回官方 Web UI/串口最小 JSON 能力核验，并固定 PC 环境；不要刷 ESP32 / 上 ROS2 救火。
- **D4 抓放失败**：缩小工作域、降低重量/速度、固定轻质方块，不尝试复杂 IK、新夹爪或重写舵机固件。
- **D5 视觉效果不稳**：先 HSV 高对比色块+固定机位，不训练新模型；保留真实帧与坐标误差。
- **D6 FPGA 还不通**：完全不影响 #10 的 PC 真视觉抓放；停止一切会替换已验板卡固件的整合冲动。
- **D7 R2 不稳**：冻结核心运动路径，取消 ROS2、NCNN、复杂语音、DPU、动态避障；将展示工位控制在现场可复现范围。
- **D9 起**：除 P0 致命 bug 外禁止升级厂家固件或改机械臂布局，留出足够时间排练与重试。

## 四、分层验收及交付证据

R0（PC 实物关节与夹爪）→ R1（PC 实体抓放）→ **R2（PC 视觉变位实体抓放与 UI）** 是主线；R3（PL 在 Z19 上实际完成小功能）是独立并行线。主线验收不用附带 FPGA 日志，但**不能因此将 PC-only 工程包装成 FPGA 实物闭环**。

每次尝试记录：`git_head`、官方 SDK/固件版本、设备端口、目标像素/桌面坐标、标定、拟定关节/末端指令、反馈、开始/完成/失败时间及视频片段。不要用一条成功录像计算成功率，也不要把模拟日志误写为实物数据。PL 若实测，另记录 bit hash、真实 MMIO/波形和配置限制。
